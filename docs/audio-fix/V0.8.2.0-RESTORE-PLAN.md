## Step 5: dosbox_uwpMain.cpp Update() — Restore accumulator loop

**File**: `dosbox-uwp/dosbox_uwpMain.cpp` — `Update()`

**Remove** HEAD accumulator (capped at 1.0):
```cpp
double now = ...;
double dt = now - m_lastAccumTime;
m_lastAccumTime = now;
m_frameAccum += dt;
if (m_frameAccum > 1.0) m_frameAccum = 1.0;
if (m_frameAccum >= 1.0) {
    RunFrameUntilFrameBoundary();
    m_frameAccum -= 1.0;
}
```

**Restore** v0.8.2.0 accumulator (multi-retro_run + queue feedback):
```cpp
double now = ...;
double dt = now - m_audioLastTick;
m_audioLastTick = now;
m_audioTimeAccumulator += dt;

int maxRetroRuns = 5;
while (m_audioTimeAccumulator >= 1.0 && maxRetroRuns > 0) {
    RunFrameUntilFrameBoundary();
    m_audioTimeAccumulator -= 1.0;
    maxRetroRuns--;
}

// Queue feedback scaling (if XAudio2 connected)
if (m_xaudio2) {
    int queueFrames = m_xaudio2->GetQueuedFrameCount();
    double targetQ = 6615.0;
    double scale = targetQ / (targetQ + (queueFrames - targetQ) * 0.25);
    if (scale < 0.9) scale = 0.9;
    if (scale > 1.1) scale = 1.1;
    m_audioTimeAccumulator *= scale;
}
```

## Step 9: Fix MAX_QUEUE flush stutter (follow-up)

**Problem**: Heavy games (Screamer) cause queue to hit MAX_QUEUE (22050), triggering
Stop/Flush/Start cycle. This causes ~50-100ms audio gaps.

**Fix options** (implement after restore, test one at a time):
1. **Increase MAX_QUEUE** from 22050 to 44100 — gives more headroom before flush
2. **Remove routine flush** — only flush as extreme safety net (if queue > 80000)
3. **Add emergency catch-up** — if queue < 500 frames, run extra RunFrame() immediately
4. **Reduce TARGET_QUEUE** from 6615 to 3307 — smaller target means more headroom

**Recommendation**: Start with option 1 (simplest), test Screamer, iterate.
